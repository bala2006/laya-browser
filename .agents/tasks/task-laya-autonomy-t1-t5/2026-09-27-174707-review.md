# T1-T5 local-first autonomy, real-model bundle, broadened benchmark, and docs (v1)

The branch raises the escalation gate to 0.85, threads the local engine's pre-escalation decision through as a fallback so an unreachable client LLM degrades to Laya's best guess instead of hard-blocking, records per-step decision latency and a run-level autonomy summary, and surfaces both in the transcript. It also adds a reproducible `prepare-model.sh` that builds either the reference or web-agent ONNX bundle without committing weights, widens the comparison benchmark from 16 to 23 real-world-shaped flows, and rewrites the README plus the PLAN.md ledger to record what was actually run. The decision pipeline order (rule seed at 0.97 -> Laya narrow decision -> confidence check with OR semantics -> escalation with Laya fallback) matches the spec, and the tests drive the real loop against a real headless Chromium rather than asserting against spies.

Watch for: (1) six newly-authored em dashes in README.md and prepare-model.sh violate the project's no-em-dash style rule (confirmed); the earlier cleanup commit only touched PLAN.md. (2) The real-model work is genuine and honestly positioned: the deterministic rules decide every structured benchmark step, so the model is a low-confidence signal behind the gate and does not change measured end-to-end outcomes (confirmed, and documented as such).

**Verdict**: NEEDS_CHANGES

## High-level view

T2's 0.85 gate lands in `config.ts` as the parsed default with OR semantics enforced in the loop (`operationConfidence < threshold || targetConfidence < threshold`), and rule seeds carrying 0.97 clear it by construction so they never escalate. T1's local-first ordering is the `policySeed -> engine.decide -> confidence check` pipeline, with the client LLM reached only inside the confidence branch.

T4 is the substantive behavioral change: `escalate()` gained an `EscalationOptions.fallback` that the loop populates with Laya's pre-escalation decision. When the sampler is absent or throws, escalation returns that fallback (when it is non-BLOCKED) with `escalated: false` and a warning note, so a single unreachable step continues on Laya's guess. A run stops for BLOCKED only when Laya itself chose BLOCKED, preserving the R2 no-weights placeholder's graceful degrade. T3's per-step scoping falls out of the pipeline running fresh each iteration; there is no latched "LLM mode."

T5 records `inferenceMs` per step (measured around the decision pipeline only, excluding action IO) and attaches an `AutonomySummary` to the result, rendered as a compact autonomy/inference line and per-step `inf=NNms`.

The real-model work builds genuine bundles through `@receptron/laya` and runs real inference behind `LAYA_MODEL_DIR`-gated tests; no weights are committed and `.gitignore` excludes them. The honest finding, recorded in the ledger, is that the rule layer decides the structured benchmark steps for both models, so the model choice does not move the end-to-end numbers.

The remaining defect is stylistic: newly-authored content reintroduces em dashes the project rule forbids.

### 0.85 gate with OR semantics (T2)

The gate is parsed once in `config.ts` (`DEFAULT_CONFIDENCE_THRESHOLD = 0.85`, clamped to `[0,1]`, `LAYA_CONFIDENCE_THRESHOLD` override) and consumed in the loop as:

```
const lowConfidence =
  decision.operationConfidence < confidenceThreshold ||
  decision.targetConfidence < confidenceThreshold;
if (decision.source !== "rule" && (lowConfidence || decision.operation === "BLOCKED")) { ... escalate ... }
```

The OR is the spec's "operation OR target head" wording, and rule-seeded steps are excluded from the check entirely, so a 0.97 seed never escalates. `config.test.ts` asserts the 0.85 default, the env override, out-of-range fallback, and override precedence, so a regression that flips the default or drops the clamp would fail.

### Escalation fallback keeps autonomy alive (T4)

The core of T4 lives in `escalation.ts`. `escalate()` computes a usable fallback only when the supplied decision is non-BLOCKED, then in both unreachable branches (no sampler, and sampler throws) returns that fallback with `escalated: false` and a warning note. The R2 no-weights placeholder is BLOCKED, so it correctly does not count as a real guess and still degrades to a clean BLOCKED. The loop threads Laya's pre-escalation `decision` in as `fallback` on every escalation, delta-prompt or not.

Two behavioral distinctions the tests pin down and that must not regress:

- An unreachable LLM with a non-BLOCKED Laya guess continues the run on that guess (`escalated: false`, source stays `laya`, warning note), rather than ending BLOCKED. `escalation.test.ts` asserts this for both the no-sampler and sampler-throws paths, and the loop-level test confirms no `llm`-sourced BLOCKED step appears.
- A run stops BLOCKED only when Laya itself chose BLOCKED with no non-BLOCKED fallback. The loop-level test with an always-BLOCKED engine and no sampler asserts `outcome === "blocked"` with the terminal step's note containing "MCP sampling", proving the fail-closed path is intact.

The `escalated` flag also gates the escalation/token accounting, so a fallback (non-escalation) does not inflate the escalation counter.

### Per-step scope and autonomous resume (T3)

The decision pipeline re-runs from the rule seed on every iteration, so escalation is inherently scoped to one step; there is no persisted "LLM mode" flag. The T3 test drives a low-confidence step 1 (escalates, source `llm`) followed by a high-confidence step 2 and asserts exactly one `llm` step at step 1, that step 2's source is not `llm`, and that the run reaches a real independent page verification. This would fail if an escalation latched or terminated the run.

### Auditability: inferenceMs and autonomy summary (T5)

`inferenceMs` is measured around `decisionStart = Date.now()` through the end of the confidence check, deliberately excluding the action IO, and is attached to every recorded step including the terminal and destructive-guard records. `summariseAutonomy` is a pure fold over the transcript sources with `fullyAutonomous = rule + laya + stub`, and it is attached at both normal return sites but omitted on the launch-free degraded return, matching its documented contract. `renderRunResult` computes a median inference time and renders `Autonomy: X/Y steps local (Z%); inference: median NN ms`. The T5 test checks finite non-negative `inferenceMs` on executed steps, the summary math invariants (`rule+laya+stub+llm === total`), and the pure/total-safe empty-transcript case.

### Escalation parser as a trust boundary

`parseDecision` guards every operation the planner may return: unknown ops, targeted ops with unresolvable refs, NAVIGATE without an absolute http(s) URL (blocking `javascript:` and protocol-relative hops), PRESS_KEY without a key, and FILL_FORM with an empty/malformed/unknown-ref batch all collapse to a well-formed BLOCKED. `escalation.test.ts` exercises each of these including the `javascript:` and `//evil.example` NAVIGATE cases. This is the right posture for input that originates from a client LLM, and the URL guard in particular is a real security control worth keeping asserted.

### Real-model bundle, no committed weights

`prepare-model.sh` builds two genuine bundles: the reference path loads the prebuilt `receptron/laya-onnx` bundle through `@receptron/laya`'s `Laya.load` with no export, and the web-agent path runs a Python 3.12 export of `abedinia/laya-web-agent` plus a documented one-line tokenizer special-token rename (same token IDs) to satisfy `@receptron/laya`'s hardcoded ModernBERT names. `git ls-files` shows no `.onnx`/`.safetensors`/`model/` tracked, and `.gitignore` excludes `*.onnx`, `*.onnx.data`, `model/`, `.venv/`, and `.cache/`. The gated real-weights tests are self-skipped without `LAYA_MODEL_DIR`, which accounts for 2 of the 3 skipped tests.

The honest finding is documented rather than papered over: on all four structured fixtures both real models show a source breakdown of 3/0/0/0 because the 0.97 rule seed clears the 0.85 gate before the model is consulted, and direct `decide` probes show neither checkpoint reliably picks the correct web operation from the `renderState` input. The recommendation to ship the zero-friction reference bundle as default while keeping the web-agent export documented is a defensible call given no evidence of end-to-end lift on these tasks. The gap worth naming: the benchmark as constituted cannot demonstrate the model's value, because the rules always win first.

### Broadened benchmark

The compare suite grows to 23 tasks spanning a validated multi-field signup, search-then-select, a two-page wizard, table row selection, consent-banner and blocking-modal dismissal, and login-then-follow-up. Each new task's `verify(h)` re-probes the real DOM for a literal outcome (e.g. `status === "Account created for ada@example.com on the pro plan"`, `chosen === "Chosen invoice INV-1002"`), so a pass reflects real page state rather than a self-reported DONE. RESULTS.md reports 23/23 for laya Assist and 20/20 for Playwright MCP with the 3-task gap attributed to storage/verify tools Playwright MCP core does not expose (marked N/A, not a loss), and the totals are internally consistent. The Autopilot-mode FAILs (login-fill-form, search-then-select, consent-dismiss, modal-dismiss) are documented as reference-stub limitations rather than loop defects, which matches the honest positioning elsewhere.
