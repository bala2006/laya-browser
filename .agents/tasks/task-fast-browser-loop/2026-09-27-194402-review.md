# Follow-up fix: align act-time guard name derivation, honest click doc, goal.ts JSDoc (v2)

Follow-up commit `5f7ab2d` on `perf/fast-browser-loop` addresses three of the five v1 findings. Finding 1: the act-time in-page `nameFor` in `currentGuardAndPageKey` (src/browser.ts) is rewritten to mirror `captureFast`'s in-page `accessibleName` (src/snapshot.ts) exactly, adding the `aria-labelledby`, input submit/button/reset `value`, `title`, and child `img[alt]` fallbacks it previously lacked, so an unchanged control named via those attributes no longer recomputes a different name and falsely re-checks as stale. Finding 2: the `actOnNode` JSDoc is corrected to describe the synthetic `el.click()` gated by the rect-center occlusion hit-test instead of claiming a real pointer click. Finding 4: the misplaced `trimUnquotedValue` JSDoc block in src/laya/goal.ts is moved above its own function. A new fixture and parity test lock the Finding-1 behavior.

Watch for: nothing blocking. The two in-page name derivations are now logically identical (**confirmed** by side-by-side read); the parity test genuinely fails when the fix is reverted (**confirmed** — reverting `nameFor` reproduces `expected false to be true`); findings 3 and 5 remain intentionally deferred as documented conservative-by-design / known-cost notes. Suite is green at 292 passed / 3 skipped and the flag-off default path is untouched.

**Verdict**: APPROVED

## High-level view

The name-derivation alignment is the substantive fix. `nameFor` now walks the same fallback chain as `accessibleName` in the same order — `aria-label`, `aria-labelledby` (split on whitespace, resolved via `getElementById`, trimmed, joined with a space), form-field `<label for>`/wrapping label/`placeholder`/`name`, input submit/button/reset `value`, `title`, `textContent` (collapsed whitespace, truncated to 117 chars + `"..."` past 120), then child `img[alt]` — using the same `CSS.escape` on the label id and the same `he.ownerDocument || document` resolution. The only textual differences are brace style (single-line `if` returns vs braced), which do not change behavior. Observe-time and act-time guards now agree for controls named via any fallback.

The new lock test captures a fixture with one button named only via `title` and one named only via a child `img[alt]`, then asserts both re-check FRESH through `freshGuard` on an unchanged page. It exercises the exact fallbacks the fix added and fails without it.

The doc fix and the goal.ts JSDoc move are text-only; both now match the code they describe.

Findings 3 (center-point-only occlusion) and 5 (fast settle still runs `probeSettle` + a second `captureFast`) were deliberately left as-is, consistent with the v1 characterization of both as conservative/known-cost rather than bugs. The v1 approval and its gating/eval-boundary/speculative-purity analysis still hold — this commit touches only the three targeted spots plus test assets.

### Name-derivation parity (Finding 1)

`accessibleName` (inside `fastWalk` in src/snapshot.ts) and `nameFor` (inside `currentGuardAndPageKey` in src/browser.ts) now walk an identical fallback chain. Reading them side by side after normalizing whitespace, the sequence is:

```
aria-label (trimmed)
  -> aria-labelledby: split /\s+/, map id -> getElementById(id)?.textContent?.trim() ?? "",
                      filter(Boolean), join(" ")  [if any]
  -> form fields (input/textarea/select):
       label[for=CSS.escape(id)] textContent
       -> closest("label") textContent
       -> placeholder
       -> name
  -> input[type=submit|button|reset] .value
  -> title
  -> textContent collapsed to single spaces, trimmed; if > 120 chars -> slice(0,117)+"..."
  -> child img[alt]
  -> ""
```

Every branch matches: the same `he.ownerDocument || document` for id lookups, the same `CSS.escape` on the label `for` id, the same `getElementById` (document-scoped, not `doc.getElementById` for labelledby in both), the same whitespace-collapse and 120/117 truncation constants, the same trim-and-guard on each attribute. The only diffs are cosmetic brace style (`if (...) return x;` vs `if (...) { return x; }`), which do not affect the returned string. No residual divergence in label lookup, aria-labelledby joining, truncation, `CSS.escape`, or `ownerDocument` handling.

Because the two derivations feed the `name` field of the `NodeGuard` compared by `guardsEqual`, a control whose name comes from `title` or a child `img[alt]` now records the same value at observe time and act time, so `freshGuard` returns fresh rather than throwing `softError("stale")` and burning self-heal budget.

### Parity lock test (verifies the fix and would fail if reverted)

`test/fixtures/fast-title-name.html` provides two buttons with no text and no `aria-label`: `#by-title` named only via `title="Settings"`, and `#by-img-alt` named via a child `<img alt="Search">`. The new test in `test/fast-loop.test.ts` captures the snapshot, locates the two controls by their derived names (`"Settings"`, `"Search"`), and asserts both re-check FRESH via `freshGuard` on the unchanged page.

Reverting `nameFor` to the pre-fix chain (dropping the `aria-labelledby`, submit-value, `title`, and `img[alt]` branches) and running this test in isolation reproduces `AssertionError: expected false to be true` at the `#by-title` assertion — the recompute yields `""` where the observed guard held `"Settings"`, so `freshGuard` reports stale. The test therefore genuinely exercises the fix and locks against regression.

### Doc corrections (Findings 2 and 4)

`actOnNode`'s JSDoc now states that `click` fires a synthetic `el.click()` after the rect-center occlusion hit-test passes, that the center coordinate gates the action but is not used to synthesize a pointer gesture, and that no full pointerdown/mousedown/mouseup sequence is dispatched the way a real pointer click would be. This matches `actOnNodeInPage`, which reaches `(el as HTMLElement).click()` on the click path after the `el.contains(document.elementFromPoint(x, y))` check. The behavioral divergence from the legacy `locator.click()` (v1 note that sites gating on pointer events behave differently under the fast path) is now honestly documented rather than contradicted.

In src/laya/goal.ts the `trimUnquotedValue` JSDoc block now sits directly above `trimUnquotedValue`, and `lastLabelWord` carries its own (correct) doc. The stacked-duplicate defect from v1 is gone.

### Regression and scope check

The full suite runs 292 passed / 3 skipped (up from v1's 291/3 by the one new parity test), all green. The commit's diff is confined to `nameFor` and the `actOnNode` doc in src/browser.ts, the JSDoc move in src/laya/goal.ts, and the new test + fixture — nothing on the flag-off path (`captureFast`/`actOnNode`/`freshGuard` are still reached only under `fastLoop`, and `fastAct` still short-circuits when `options.fast` is absent). No em dashes appear on any added line. The v1 gating, untrusted-eval-boundary, and speculative-decide-purity conclusions are unaffected by this commit and continue to hold.
