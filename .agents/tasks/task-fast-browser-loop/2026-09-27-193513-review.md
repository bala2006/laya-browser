# Flag-gated fast browser loop for laya-browser-mcp Autopilot (v1)

Adds an opt-in fast Autopilot perception/act path (`LAYA_FAST_LOOP`, default OFF) that adopts the jev-ultrafast mechanics in TypeScript/Playwright: one atomic `captureFast` evaluate that builds a persistent in-page node-identity map with per-node semantic guards, a page marker and a pageKey; a per-node freshness re-check plus a pre-input occlusion hit-test before acting on the observed node (no fresh selector query); a bounded adaptive wait; a widened local goal grammar; and a speculative-decide-during-settle overlap. It also ships three deterministic local fixtures, an honest before/after benchmark, and evidence-labeled docs. The whole feature is gated so the default path is unchanged.

Watch for: (1) the act-time guard recomputation in `currentGuardAndPageKey` derives the accessible name from FEWER fallbacks than `captureFast`'s `accessibleName` (no `title`/`img[alt]`), so controls named via those attributes will re-check as stale and needlessly fall back to self-heal (**likely**). (2) `actOnNodeInPage` performs a synthetic `el.click()` and single-point occlusion test, which diverges from Playwright's real pointer click and can false-negative on large partially-covered controls (**confirmed** divergence, **possible** real-automation impact). Both are fast-path-only and self-heal-recoverable; neither affects the default path.

**Verdict**: APPROVED

## High-level view

The gating is clean. Every fast-path entry point (`captureFast`, `freshGuard`, `actOnNode`, `adaptiveWait`, the speculative prefetch/decide) is reached only under `fastLoop`, and `fastAct` short-circuits when `options.fast` is absent. With the flag off the capture/resolveRef/locate/probeSettle path is untouched; the suite confirms this (291 passed / 3 skipped, +28 new tests, no regressions).

The untrusted `page.evaluate` boundary is validated on the real path: `captureFast` calls `assertRawFastSnapshot` before any field is trusted, and the predicate checks every string field, the controls array, each control's integer `nodeId`, the full guard struct, and the numeric rect. A malformed structure throws rather than propagating.

The speculative-decide is a genuine pure optimization. It only caches decisions the confidence gate would accept without escalating, is re-validated by the FEAT-002 freshness check at the next step top, and is discarded on any drift. Behavioral tests assert the observed decision sequence is byte-identical with speculation on vs off, that reuse actually happens (no double-decide), and that drift discards the cache.

The freshness guard and act-time execution recompute node state in-page. The main gap is that the act-time name derivation is a narrower reimplementation of the capture-time one, so a subset of controls will re-check as stale even when unchanged. This never produces a wrong action (it degrades to self-heal), but it erodes the intended round-trip win for those controls.

The benchmark is honest: it reports the fast loop as a few percent SLOWER on instant local fixtures with identical steps/round-trips and no correctness regression, and it publishes NO jev head-to-head number because jev cannot run here. Doc claims carry measured/inferred labels.

<summary>Issues (5)</summary>

1. **Guard name-derivation divergence** — `currentGuardAndPageKey.nameFor` omits the `title` and `img[alt]` fallbacks that `captureFast.accessibleName` uses, so a control named via those attributes recomputes a different `name`, fails `guardsEqual`, and falls back to self-heal even when fresh. Factor the name/role/guard computation into one shared in-page routine both call, or drop `name` from the guard comparison.
2. **Synthetic click vs real pointer click** — `actOnNodeInPage` fires `el.click()` rather than a real pointer click at the rect center, and the doc comment on `actOnNode` claims a "real click at the rect center via the element handle". Reconcile the comment with the behavior, and consider that `el.click()` bypasses pointer/mouse event listeners some sites depend on.
3. **Center-point occlusion false-negatives** — the occlusion test only samples the rect center; a large control whose center is covered but whose edges are clickable is rejected as `covered`. Acceptable as conservative, but worth a note; consider sampling a few points for large rects.
4. **Duplicate JSDoc block in goal.ts** — `lastLabelWord` is preceded by two stacked `/** ... */` comments, the first of which actually describes `trimUnquotedValue`. Remove the misplaced block.
5. **Fast settle probe still runs `probeSettle` + a second `captureFast`** — on the fast path the settle branch runs `probeSettle` and a speculative `captureFast` even though the targeted action already did `adaptiveWait`; this is the fixed overhead the benchmark measures as a few percent slowdown on instant fixtures. Not a bug; flag as the known cost.

<summary>Details</summary>

### Flag gating and the untouched default path

`fastLoop` defaults to `false` in `config.ts` (`envBoolDefaultFalse`, only literal `"true"` enables it) and threads through `server.ts` -> `run_goal.ts` -> `runGoal`. In the loop, the capture branch is `if (fastLoop) { ... } else { legacy }`, the execute options only carry `fast` when `fastLoop && fastCtx !== undefined`, `fastAct` returns `{ handled: false }` when `options.fast` is absent (so every targeted op falls through to `session.locate`), and the speculative settle branch is `settleProbe && fastLoop`. Nothing on the flag-off path calls `captureFast`/`actOnNode`/`freshGuard`. The +28 tests land on top of the unchanged 263/3 baseline.

### Untrusted eval boundary

`captureFast` runs `assertRawFastSnapshot(raw)` on the `page.evaluate` output before mapping any field into a `FastControl`. `isRawFastSnapshot` rejects a non-object, wrong-typed string fields, a non-array `controls`, a non-integer `index`/`nodeId`, a malformed guard (each scalar or null checked field-wise), and a malformed rect. The boundary-validation test exercises the null/non-object, missing-string, non-array-controls, non-integer-nodeId, bad-guard, and short-rect cases against the exported predicate, so a regression in the validator would fail. This is the right posture for a trust boundary and it is applied on the production path, not only in tests.

### Speculative-decide purity

```
step N settle:  probeSettle || captureFast  (concurrent)
                if !changed: cache {snapshot, ctx} + computeSpeculativeDecision(state)
step N+1 top:   canReuseFast = fastLoop && cached && !autoDismiss
                if canReuseFast && speculativeTargetFresh(decision): reuse
                else: decide fresh (normal pipeline)
```

`computeSpeculativeDecision` mirrors the pipeline order (`policySeed` -> `engine.decide` -> `refineWithGoalValue`) and returns `undefined` for anything the real step would escalate or BLOCK, so the observable escalation always runs on the real iteration. Reuse is gated on the cache being computed against the very snapshot in use (`canReuseFast`) and on `speculativeTargetFresh` re-checking each target's guard+pageKey (targeted ops) or the whole-page marker (non-targeted). The `speculative decide during settle` tests assert an identical decision sequence and outcome with the flag on vs off for both a stable-page (reuse) and a drifting-page (discard) engine, and assert the decide count stays within one of the non-speculating count (proving reuse, not a hidden double-decide). This is a convincing purity argument.

### Guard recomputation divergence (the real concern)

The freshness re-check compares a `NodeGuard` captured by `captureFast`'s `accessibleName` against one recomputed by `currentGuardAndPageKey`'s `nameFor`. `accessibleName` has a longer fallback chain: `aria-label` -> `aria-labelledby` -> label/placeholder/name (for form fields) -> input submit value -> `title` -> textContent -> child `img[alt]`. `nameFor` stops after textContent and omits the `title` and `img[alt]` fallbacks. For a control whose accessible name comes from `title` or a child image alt, the observe-time guard records that name while the act-time recompute records `""` (or the textContent), so `guardsEqual` returns false and `fastAct` throws a `softError("stale")`. The self-heal budget then re-captures and re-resolves, so the action still succeeds and no wrong node is touched, but the intended "act on the observed node with no fresh query" win is lost for exactly those controls, and on `selfHealRetries: 0` the step would surface as a stale-ref failure it should not. The two in-page name/role/guard computations should be one shared routine so they cannot drift; alternatively drop `name` (a derived, fragile field) from the guard equality and rely on `value`/`scopeText`/aria state.

### actOnNode click semantics and occlusion

`actOnNodeInPage` re-checks connected/visible/enabled/not-readonly, rejects a zero-size or off-viewport rect as `covered`, then requires `el.contains(document.elementFromPoint(centerX, centerY))` before acting. For `click` it calls `el.click()`. Two notes: the `actOnNode` doc comment says a click is "issued at the rect center via the element handle", which does not match the in-page synthetic `el.click()` (no real pointer/mouse events, no hover, center coordinate unused for the click itself) - reconcile the comment or the behavior, since sites that gate on `pointerdown`/`mousedown` will behave differently under the fast path than under the legacy `locator.click()`. And the single center-point hit-test will reject a large control whose center is occluded but whose edges are actionable; conservative and safe (it degrades to re-observe), but a source of avoidable false-negatives for wide toolbars/sticky-header overlaps. The occlusion test proves the covered->uncovered transition works, so the mechanism is sound; these are edge refinements.

### Widened goal grammar

`goalAssignments` now accepts unquoted email/date tokens (anchored `EMAIL_RE`/`DATE_RE` on the first token) and unquoted multi-word values trimmed at a clause boundary (`,`/`;`/`and`/`then`/trailing period), with quoted values still taking precedence and a leading joining word stripped from the key. `keyMatchScore` replaces the boolean match so a multi-field goal routes each value to its best-scoring field (`last name` -> "Last name" over "First name"), with first-positive-wins preserved for the single-match case. `goal-policy.test.ts` covers these. One cosmetic defect: `lastLabelWord` carries two stacked JSDoc blocks, the first describing `trimUnquotedValue`; remove the misplaced one.

### Benchmark honesty

`before-after.mjs` runs laya's own `laya_run_goal` with the flag off vs on against the deterministic fixtures and reports wall-clock/steps/round-trips with `verify()` re-probing the real DOM. RESULTS.md reports the fast loop as -4% to -10% wall-clock (SLOWER) with identical steps and browser round-trips and PASS/PASS verification, and explains why (no RTT to amortize on instant local fixtures; the guard/occlusion/adaptive-wait/second-captureFast evaluates are fixed overhead). The README/PLAN state jev is NOT runnable here (missing `TYPESAFE_API_KEY`/model endpoint) and publish NO jev number, labeling the comparison qualitative/INFERRED and citing jev's own figure as theirs. No fabricated numbers, em-dash-free added lines, and no committed weights. This is the honest outcome the brief asked for.
